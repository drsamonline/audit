## 1. The PDF toolchain, and the licence nobody checks

Six libraries matter, and their licences are not interchangeable:

| library | licence | weight | what it is for |
|---|---|---|---|
| **pypdf** | **BSD-3-Clause** | pure Python, no deps | text extraction, page merge/split, metadata. Slow on large files, no layout |
| **pdfminer.six** | **MIT** | pure Python | character-level layout analysis; the engine under pdfplumber |
| **pdfplumber** | **MIT** | pure Python + pdfminer | tables, bounding boxes, visual debugging — the best pure-Python table extractor |
| **pypdfium2** | Apache-2.0 + BSD-3 + **LGPL-3.0** component | binary wheels | rendering and fast text via **PDFium**, Chrome's engine |
| **pikepdf** | **MPL-2.0** | binary wheels (qpdf) | structural edits, repair, encryption — file-level copyleft only |
| **PyMuPDF** | **AGPL-3.0** | binary wheels | fast render + text; **the licence that changes what you can ship** |

### The finding: corpus-extendum already depends on AGPL

`corpus-extendum/docs/PIPELINE.md` names **PyMuPDF** for rendering plates and handling SVG. That is
AGPL-3.0.

- **Outputs are unaffected.** Books the pipeline produces are not derived works of the tool.
- **A build tool used locally is fine.** AGPL's network clause bites when *users interact with the
  program over a network*, not when a program writes files.
- **Two things do bite.** If corpus-extendum is ever served as a web app, or if its licence is ever
  changed away from AGPL, PyMuPDF must already be gone. A permissive pipeline is a licence the owner
  keeps control of.

**Action:** replace PyMuPDF with **pypdfium2** for rendering and **pypdf / pdfminer.six** for text —
same capabilities, no copyleft, and pypdfium2 is Chrome's PDFium rather than a re-implementation.
This is a licence-risk removal, not a feature.

### What each repo should use

| repo | text | tables | render | licence position |
|---|---|---|---|---|
| **lexora** (`[pdf]` extra) | docling (MIT), fallback pypdf | pdfplumber | — | all permissive |
| **corpus-extendum** | docling or pdfminer.six | pdfplumber | **pypdfium2, replacing PyMuPDF** | removes the only AGPL dependency |
| **All4ONE** (24 PDF tools, single portable binary) | **pypdf** | pdfplumber | pypdfium2 | pure-Python where possible; wheels only if the binary can carry them |
| **heavenzip** (spawns) | docling | — | — | process boundary, any licence |
| **materia medica family** (scanned books) | MinerU **rejected**; docling with OCR extra | pdfplumber | pypdfium2 | permissive only |

**MinerU stays rejected**: Apache-2.0 plus commercial thresholds, an attribution obligation, and
automatic termination if it is missed. No fee at this scale, but it buys nothing docling does not.

## 2. The plan, in the order to work

Each item says why it is at that position. Nothing here is speculative: every one has a measured
number or a named licence behind it.

### 1. ziptastic — benchmark against OpenZL  ·  **BLOCKED, see `openzl-benchmark-attempt-2026-11-18.md`**

The attempt: PyPI wheel installs but carries no prebuilt graph; no Linux CLI binary exists; `make` is absent and the unconditional SDDL compilers make the CMake build cost ~1 object per 280-second call. Needs a machine with `make`.

**Why first:** it is the only item that can invalidate a claim rather than add one. OpenZL is BSD,
format-aware, in production at Meta, and has **no canonicaliser** — the first external yardstick
Layer 0 has ever faced. If the engine only ties it, the product claim changes, and everything below
is worth less.
**Effort:** small. **Risk:** it may say something uncomfortable, which is the point.

### 2. corpus-extendum — replace PyMuPDF with pypdfium2  ·  **DONE 2026-11-18, partially**

Three of four PDF-render sites moved to PDFium (mean pixel difference 0.86/255, 1.49% of pixels above 8). PyMuPDF stays for **SVG plates only** — PDFium cannot open SVG, cairosvg blackens these plates, WeasyPrint is the cost D7 avoids. D12 records it. What would finish it: `resvg` (MPL-2.0), verified against the black-square failure.

**Why second:** it is the only *licence* risk on the list, in a repo that already ships. Every day it
sits there is a day the pipeline cannot be served or relicensed without a rewrite.
**Effort:** small — rendering calls only. **Verification:** the vault's own dedupe hashes must not
move; the plates must be byte-comparable.

### 3. corpus-extendum — docling for the text step  ·  **REJECTED 2026-11-18, measured**

Install is **6.4 GB** (torch 1.2 GB + 3.0 GB CUDA), it cannot initialise in 2 GB RAM, and the current spine extractor reproduces the shipped text at **100.00% similarity** — the text is authored XHTML, not a rendering, so there is nothing to infer. D13 in corpus-extendum records it.

**Why third:** the pipeline's weakest stage. It extracts text from the EPUB spine and requires
`_djvu.txt` for scans. docling is MIT, local, air-gapped, reads EPUB *and* PDF, and exports lossless
JSON — the structured sibling of the plain text it produces now.
**Effort:** small to wire, medium to validate against the existing shelf.

### 4. ~~heavenzip — the PE fallback order and the scoring function~~  ·  **WITHDRAWN 2026-11-18**

Both transfers were mis-assigned. heavenzip **compresses**; its commands are `validate`, `detect`,
`compress`, `decompress`, `bench`, and it never opens a third-party archive, so a self-extracting
installer is not its problem. And it has no multi-detector evidence to score — `matches()` is one
boolean class gate and the profile is named explicitly — so extractcode's formula would invent
inputs heavenzip does not have.

**Both move to kosh (item 9), with evidence:** `sniff()` in `kosh/core/optimize.py` recognises
**four** signatures — png, gzip, zip, jpeg — and returns `"unknown"` for everything else. Against
UniPyX's 777 rules, that is the gap the detection work should close.

What does fit heavenzip from the surveys is Carpentieri's scheduling, and that is a design item.

### 5. ziptastic — Pareto reporting  ·  **DONE 2026-11-18** (ziptastic#56)

`scripts/pareto.py` + `docs/PARETO.md`. Measured on the four-class corpus: `--max-ratio` is **strictly dominated on diagram.png** (same 938 bytes, twice the time), `photo.pdf` is setting-independent, `ui.png` has a genuine three-point frontier. It also exposed that bare `bench` measures **without precompression** — 86,626 where `-9` gives 51,822 — which PARETO.md now states. The hidden-test-set half is still open.

**Why fifth:** cheap, and it is the guard against the failure this week produced four times — the
64 KiB sample, the formula PNG, the gzip XML, the synthetic LZ4 frame were all measured on files I
chose. Reporting a frontier instead of a number, and holding files back, is the structural fix.
**Effort:** small. **Depends on:** nothing.

### 6. ziptastic — column-aware encodings under the SQLite transform
**Why sixth, not first:** the largest ratio opportunity on the list, and the one that needs real
design. The transform groups pages by B-tree kind and stops; delta / RLE / frame-of-reference under
the block loop is the named gap, with the ClickHouse taxonomy to work from and the 27.8% measured
baseline to beat.
**Effort:** medium.

### 7. lexora — release
**Why seventh:** it has 716 tests, a benchmark protocol stronger than the fleet's, and no release.
The same call that produced ziptastic 1.4.4 and 1.4.5 today. Do it after the two corpus-extendum
items, because the PDF decision lands in the same session's context.
**Effort:** small.

### 8. HCS — three sources and a licence column that can say "plus terms"
**Why eighth:** OpenZL (BSD), docling (MIT) and pypdfium2 (Apache-2.0/BSD-3) are all vault candidates;
and the `license` column currently cannot express "Apache-2.0 + additional terms", which is what
MinerU needed and what any future such source will need. Schema work, not code.
**Effort:** small.

### 9. kosh — `scan` ordering, and docling behind a `convert` verb
**Why ninth:** kosh already drives the engine and already has a document-facing surface. The
detection ordering from uniextract2 and magic-extractor is the same problem `scan` solves.
**Effort:** small to medium.

### 10. materia medica family — confirm the source format before choosing a tool
**Why last:** the fit was inferred from descriptions, not read. If those books are already
transcribed, the extraction tools add nothing and this item disappears. **Check first, then decide.**
**Effort:** trivial to check.

## 3. What is explicitly not in this plan

- **MinerU** — rejected on licence terms.
- **OpenZL as a dependency** — a benchmark first, a source second, never a link until it earns it.
- **Column encodings in lexora** — the numeric corpus category does not exist yet.
- **Anything for the games, `NEO`, `The_Browser`, `tessera`, `sui`, `pico`** — neither survey has
  anything for them, and inventing a fit wastes time.
- **The 12% table cost on 1 KB archives** (ziptastic §7) — a format change for 12 bytes, deferred by
  the owner's own earlier reasoning.

## 4. The one-line version

**OpenZL benchmark → PyMuPDF out of corpus-extendum → docling into corpus-extendum → heavenzip's two
small pieces → ziptastic's reporting discipline → the SQLite column transform → lexora release →
HCS sources → kosh → confirm the materia medica question.**

The first three all touch things that already ship. That is deliberate: a licence risk and a stale
measurement in a released project outrank any new feature.

# Revised 2026-11-18 (evening), after the fifty-repo survey

New facts changed the order. Recorded here rather than rewritten above, so the earlier reasoning
stays visible.

## What changed

| finding | effect on the plan |
|---|---|
| **liblz4 1.11.0 exists and changed the matcher** | the LZ4 decision is no longer "widen backwards". It is answered in `ziptastic/docs/LZ4_MEASURED.md` (PR #57): the change is **one line**, reached only by **sub-64 KiB blocks through a re-used streaming context**, so the boundary is per frame. **New step: bump the vendored liblz4 to 1.11.0 and count how many frames change.** |
| **c-blosc2 is BSD and ships shuffle/bitshuffle/delta filters** | plan item 6 (SQLite column encodings) has a reference implementation to read. **New step: read its filters before designing ours.** |
| **DwarFS clusters by similarity hash** | a corpus-level idea heavenzip does not have. Read-only prior art, mixed licence. |
| **lzbench is the fair external harness** | and it needs `make`, the same blocker as OpenZL |
| **HCS has no entry for bzip2, lrzip, blosc, libarchive, 7zip** | vault work, cheap |

## The revised order

| # | step | why here |
|---|---|---|
| **1** | **liblz4 version question — ANSWERED AND MEASURED** (ziptastic #57, #58) | source diff: one behavioural line, reached only by sub-64 KiB blocks through a re-used context. Measured: **14 of 14 cells byte-identical** across 7 inputs × 2 modes. The bump is free on everything measured; a residual corner no fixture reached. Next action is the bump itself, gated by the corpus |
| **2** | **HCS: add bzip2, lrzip, c-blosc2, libarchive, 7zip entries** | cheap, and it is the precondition for using any of them |
| **3** | **Column filters — probe shipped, result NOT VALID** (ziptastic #59) | blosc2's shuffle+bytedelta on the SQLite integer payload: 800,000 B → 411 B (99%). **But both fixtures are formula-generated**, so it does not count — the BMP trap. No real database exists in this environment (avahi's is not SQLite; lexora's holds 8 bytes). `scripts/column_filter_probe.py` is the command that closes it on a real file. **Transform unstarted by choice.** |
| **4** | **ziptastic: the holdout set — DONE** (ziptastic #60) | four frozen files no transform was designed against, hashed, with a byte-regression check. Proven both ways: an edit reports HASH DRIFT, restoring reports clean. It is a **cost gate, not a correctness gate**, and four files are a floor not a census — both said in `docs/HOLDOUT.md` |
| **5** | **lexora release — DONE 2026-11-18** | **v0.2.0-alpha.1** released with wheel + sdist attached. The wheel was downloaded back from the release, installed in a clean venv and answers `lexora 0.2.0a1` — which is the fix this release carries, since the last cut shipped a binary that named a version that never existed. Hashes corrected after a rebuild produced different bytes: they are the attached files' hashes, not a reproducibility claim |
| **6** | **kosh `sniff()` — DONE 2026-11-18** (kosh #23) | 4 signatures → **23 signatures / 21 formats**, each verified against a real file produced by the tool that writes it. Capability split from detection: `can_optimise()` says what kosh can re-encode (4), so the CLI now says `no optimiser (xz)` instead of `unsupported format`. Not 777 — UniPyX's table is unlicensed — but every entry here is proven. |
| **7** | **Install `make`** | unblocks OpenZL, lzbench, and every future build at once |
| **8** | **heavenzip similarity ordering — DONE 2026-11-18** (heavenzip #96) | DwarFS's LSH implemented from its published description (GPL-3.0 reference, MIT implementation). **Measured, including where it hurts**: +19.1% (zlib) and +24.0% (zstd) on a 1.4 MB corpus whose names interleave; **−1.1% / −3.8% when files are already adjacent**; +0.6% with a 64 MB window. So the feature is conditional, and the condition is measurable before acting. `--selftest` runs in CI |
| **9** | **materia medica: confirm source format before choosing a tool** | still unverified |

Items 1 and 2 need no compiler, no network beyond a fetch, and no owner decision. They start now.
