## 3. The measurement chain, in one paragraph per link

1. **OpenZL was never blocked by `make`.** CMake drives Ninja; `ulimit -v` is soft; the real cost is
   xgboost's `ExternalProject`. Built in 484 objects with zig cc. `serial` loses on ratio and wins
   hugely on speed; **a format-aware profile wins by half** (`sao`: −46.6%).
2. **lzbench needed no build either** — prebuilt Linux binaries exist. Nine codecs, one corpus:
   ziptastic first on ratio (20.48%), **last on speed (0.26 MB/s)**, and beaten by bzip3 on every
   text file.
3. **The BWT candidate is chosen and pays** (−4.83% overall if removed) — the gap to bzip3 is the
   implementation, not the selector.
4. **The gap is the block size, not the coder.** No residual redundancy in libbsc output; a generic
   coder on the same BWT is 8–26% worse. 16 MiB blocks: −4.27% on text.
5. **Policy shipped**: 4 MiB at/below 8 MiB, 16 MiB above. Holdout untouched (+0 bytes).
6. **Two files never entered the block loop** — whole-stream `LZMA2_FALLBACK`. That also corrects
   the non-text number: +1.30% on the two files that can respond, 0% on the two that cannot.
7. **liblz4 1.11.1**: 24 cells, no frame divergence, salvage still pays 38.7%; HCS row is a real pin.
8. **`webster`** is PPMd-owned; both PPMd knobs measured dead. The remaining gap is bzip3's coder
   family, not a setting — recorded as not worth a backend for one file.

## 4. Traps this session produced (continuing from 9)

10. **A limit you can raise is not a limit.** `ulimit -v` reports 1,536,000 KiB with an unlimited
    hard limit. Two merged PRs said "the build cannot run here" before anyone tried
    `ulimit -v unlimited`. Also: a comment saying something is impossible stops the next person.
11. **A README claim with no gate drifts.** faztest shipped "beats xz and 7z" unmeasured; the gate
    is `scripts/check-claims.py`, and it would have failed the original sentence.
12. **A test that always fails is a test nobody reads.** faztest's benchmark test timed out at 5 s
    on every run; the suite reported 5 tests, 4 passing.
13. **A corpus table mixing fallback files with block-loop files measures two machines.** Check
    `ziptastic info`'s mode column before trusting a cell.
14. **When a cell does not move, check the feature was reached at all.** `samba`/`sao` were identical
    at two block sizes because they are one whole-stream LZMA2 block — `-b` never applied.
15. **A fixture that lies.** A 9 MiB repetitive-text fixture produced **one block at `-b 4096`**,
    because dedup collapses the repetition before the block loop. Incompressible data gave right
    counts but 35 s per run — the assertion became a unit test on the pure function instead.
16. **`/tmp` is a 64 MB tmpfs.** A 9 MB fixture plus archives hit "No space left on device"
    mid-test. Everything goes under `/scratch/work`.
17. **A `copy` pin is a TODO with a date on it.** lz4 was `copy` only because upstream had not tagged
    the version the tree carried; tagging 1.11.1 closed it for one commit.
18. **Two experiments can target the wrong hypothesis.** "The coder is weaker" was plausible, written
    down as the next step, and false. A 60-line probe settled it; another argument would not have.

## 5. Environment, so the next session starts in 5 minutes

```bash
pip install ziglang cmake ninja
ZIG=$(python3 -c 'import ziglang,os;print(os.path.dirname(ziglang.__file__))')/zig
printf '#!/bin/sh\nexec %s cc  -target x86_64-linux-gnu "$@"\n' "$ZIG" > /scratch/work/tc/zigcc
printf '#!/bin/sh\nexec %s c++ -target x86_64-linux-gnu "$@"\n' "$ZIG" > /scratch/work/tc/zigcxx
chmod +x /scratch/work/tc/zigcc /scratch/work/tc/zigcxx
ulimit -v unlimited                       # or nothing large builds
cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=Release \
  -DCMAKE_C_COMPILER=/scratch/work/tc/zigcc -DCMAKE_CXX_COMPILER=/scratch/work/tc/zigcxx
cmake --build build -j3 --target ziptastic   # per-target, or a 5-minute limit eats it
```

There is **no `make`**, and nothing needs one. `mozilla` (51 MB) still does not finish `-9` inside a
300-second call at any block size — it is the one number every table in this thread carries as two
halves or not at all.
