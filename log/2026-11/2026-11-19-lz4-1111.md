# liblz4 bumped to 1.11.1 — zero frames changed

Date: 2026-11-19 · Repos `drsamonline/ziptastic`, `audit` · ziptastic PR #68

The last open item in `LZ4_MEASURED.md` was "bump to 1.11.0 and record how many frames changed". Done,
one version later, and the count is zero.

## Why 1.11.1

Upstream shipped **1.11.1** six days after 1.11.0 (2026-11-10). Diffing `lib/`: ppc64 fast-decode
paths, CLI fixes, and one library fix — `LZ4_resetStreamHC()` could write **out of bounds** at
levels ≥ 10 on a garbage state (since 1.11.0). The match finder is untouched, so the earlier 14-of-14
measurement against 1.11.0 carries, and a decompressor should link the point fix.

The 1.10.1 → 1.11.0 behavioural line is present exactly as recorded:

```c
-            {   U32 const ctxIndex = prevIndex + 1;
+                U32 const ctxIndex = ((usedTable && (prevIndex < startIndex)) ? startIndex : prevIndex) + 1;
```

## Frames changed: 0 of 10

Both encoders through the same probe — one-shot 4 MB linked and streaming 16 KiB (the path that
reaches `dictSmall`) — on a tar of the repo's docs plus four fixtures built for the stale table
entries the change is about. Size and FNV-1a identical in every cell:

| input | one-shot | streaming |
|---|---|---|
| `docs.tar` 880,640 | 524,452 → 524,452 | 524,452 → 524,452 |
| `periodic4k.bin` | 52 → 52 | 52 → 52 |
| `rand_then_repeat.bin` | 94,314 → 94,314 | 94,314 → 94,314 |
| `shift.bin` | 1,615 → 1,615 | 1,601 → 1,601 |
| `zeros_then_text.bin` | 371 → 371 | 371 → 371 |

With the earlier 14 of 14 against 1.11.0: **24 cells, no divergence**. Residual risk unchanged — a
stale slot that also survives the `dictSmall` range check.
